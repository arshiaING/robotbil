# Arbeidslogg

Her samler vi arbeidsøktene. Vi skriver hva vi gjorde, hvem som jobbet og hva neste steg er.
Vi fyller inn faktisk arbeid. Oppgaver vi skal gjøre senere står i prosjektplanen.

## Arbeidsøkter



Under ligger malen vi bruker til nye arbeidsøkter.

## Hvordan vi bruker loggen

Vi skriver dato og navn for hver arbeidsøkt. Hvis flere jobber samme dag, kan vi skrive øktene sammen.
Bruk malen under når vi skal føre en økt.

Tester føres i [testloggen](../testlogg/README.md). Her holder det å vise til test-ID og skrive en kort oppsummering.
Hvis vi endrer ledninger, oppdaterer vi også [koblingsoversikten](../kobling/README.md).

## Mal for en arbeidsøkt

```markdown
# Arbeidslogg - [dato]

- Hvem jobbet: [navn]
- Hva vi gjorde: [faktisk arbeid]
- Programmering: [hvem skrev eller endret hvilke deler, eller ikke aktuelt]
- Status: [planlagt, skrevet, kompilert eller fysisk testet]
- Hva vi testet: [test-ID og kort resultat, eller ikke testet]
- Problemer: [det som ikke fungerte eller fortsatt er uklart]
- Dokumentasjon: [hva som ble oppdatert]
- Neste steg: [hva vi skal gjøre videre]
```

Bruk datoen arbeidet faktisk ble gjort. Hvis vi retter en oppføring, skal det være tydelig hva vi har rettet.
